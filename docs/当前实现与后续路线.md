# chess-coach 当前实现与后续路线

现有教程、知识点讲解、经典开局教学和 AI 课程推荐已暂停展示，等待逐课校对。下架前的课程、知识点、例局和来源材料已备份至 [教程快照](archive/chess-coach-tutorials-before-unpublish.zip)。题库、内部标签、复盘和 SQLite 学习记录继续保留。恢复发布前逐课核对正文、实际回放的局面与配套练习。

核对日期为 2026-11-15。本文以当前 `src/`、`web/` 和本地 SQLite 为准，`_legacy/` 用来理解早期方案。代码核对确认了 25 个知识点、20 节课程、12 组经典开局、33 条开局变化和 34,747 道入库题。当前前端通过 JavaScript 语法检查，后端可导入并生成 26 个 OpenAPI 路径。本轮未逐页在浏览器验收，也未重新调用在线模型。

## 产品方向：先做个人版，再做公开网页版

| 版本 | 用户怎么用 | 数据与模型 |
| --- | --- | --- |
| **个人国际象棋教练（先做）** | 下载后在本机启动，浏览器打开本地页面，直接使用。去掉登录、注册、退出和游客切换；首次启动自动建立一个本地档案。 | 学习进度、题目记录、AI 计划、PGN、复盘结果和继续位置存本机 SQLite。用户自行配置模型 API 地址、模型名和密钥，密钥交给本地后端；未配置时题库、教程和 Stockfish 复盘仍可用，AI 计划使用本地规则。 |
| **公开网页版（后做）** | 用户打开公网网址即可使用，不用下载安装或自己接 API。 | 由服务端提供模型与引擎，后续单独设计记录归属、用户隔离与资源配额。复用已经验收的复盘、题库和课程逻辑。 |

个人版底座已实现。程序监听 `127.0.0.1`，自动使用 SQLite 中的本地档案。复盘页可恢复多盘棋及各自的停止位置。模型保持自配 API、WorkBuddy / CodeBuddy CLI 和本地规则的调用顺序。可以在备份后选用旧档案。旧浏览器缓存中的 PGN 可以重新导入和分析。操作见 [README](../README.md)。下方「前端」「后端」记录的是个人版改造前的基线。

## 复盘优化重点：多路证据统一精排

同一转折点只保留一个教学解释区。Stockfish 给出推荐着与实战着的可回放对照；战术核验判断是否有可证的将杀或直接得子；BinProp 提供两条变化中可观察到的棋理差异；相似题检索判断有没有同一机制的题可用来练习。这几路先各自产出候选，再统一核验、去重和精排。相似题可以佐证「机制可迁移」，不能单凭相似就反推原局面的错误原因。

1. **统一证据格式。** 每个候选记录转折点、执子视角、对应棋步和变化、来源、核验结果。排序先看证据是否充分，再看能否解释推荐着和实战着的差别、是否值得讲。按同一机制合并术语重复的候选；有反例或冲突没解决的候选不展示。
2. **少讲，但每条能回到棋盘上核对。** 每处先保留一个主解释，有充分证据时再补一个。强制将杀须核验合法防守；得子须考虑反击；BinProp 的统计差异须能定位到对应棋步，只能支持该样本范围内的描述。八套共 192 个函数作为待评估的候选库，以当前启用的 30 个为基线，逐套测增益、重复、误报和延时。没有可靠解释时保留评估和走法；没有同机制题就不推荐。
3. **明确 Stockfish 推演长度。** 关键转折点的推荐着和实战着都按目标 **6 个完整回合、常规局面至少 5 个完整回合** 推演和回放，两边从各自的分叉首着起算，合计为每条 12 手或至少 10 手（ply）。目前整盘分析的主变化最多保留 8 手，摘要只预览 5 手，BinProp 的取样上限也与主变化不同。先保留整盘快扫，只对关键点加预算；前后端统一长度口径。将杀或和棋提前结束时显示完整短线；因预算不足达不到下限时标明「分析不足」，不补走法。推演长度与引擎搜索深度分别设置。

## 接下来做什么

| 顺序 | 交付 | 验收点 |
| --- | --- | --- |
| **P0 · 个人版底座（已实现）** | 个人版自动打开本地档案，学习记录与完整复盘写入 SQLite，保留自配 API 和 WorkBuddy。提供旧档案选用、备份、恢复及旧 PGN 重分析。 | 发布前仍需在干净 Windows 环境进行浏览器验收和在线模型联调。 |

| **后续 · 公开网页版** | 复用经过个人版验证的核心流程，单独设计托管模型、部署、用户数据隔离和引擎容量。 | 用户直接打开网页即可开始使用，数据访问范围和资源成本可以验证。 |
